# D-018 — Web Client–Server Platform

- **Status** APPROVED for product direction, 2026-11-11. Implementation and release evidence pending.
- **Context** Soul of Meal should feel like a continuous anime game client accessed through a browser. Accounts, progression and inventory require server ownership.
- **Decision** Target Phaser 4 + TypeScript + WebGL, React for login/forms/overlays, Spine 2D with sprite atlases, ASP.NET Core, PostgreSQL, Redis, SignalR/WebSocket and Object Storage/CDN. Use 1920×1080 16:9 as the desktop design frame. Verify responsive layouts and safe areas.
- **Supersedes** The named-engine deferral in D-001, the local-first production persistence choice in D-003 and the portrait-first Home default in D-015. Benchmark and responsive evidence, asset review under D-002, bot-only P0 under D-004 and content scope under D-017 still govern their areas.
- **Implementation** Reuse existing rules, IDs, art and AI Sprite Agent exports. Port client presentation and game state authority in stages. See the [architecture](../../03_engineering/ENGINE_ARCHITECTURE.md), [web asset pipeline](../../02_art/WEB_ASSET_PIPELINE.md) and [concept audit](../../04_qa/PLAYTEST_CONCEPT_GAP.md).
- **Acceptance** Login → Loading → Home and all three playable modes use one browser application. An authenticated player can continue progress from another browser. Versioned asset rollout and rollback preserve active match compatibility. Capture actual-device browser benchmarks before production acceptance.
